# Network Intrusion Detection Generalization Analysis

An exploratory study of how intrusion-detection models trained on CIC-IDS2017 behave under different evaluation conditions, including a random train/test split and testing across collection days.

The main observation is that **high recall in the saved random-split evaluation did not carry over to a Friday-to-Wednesday evaluation**. The comparison also changes which attack types are present, so the result should **not** be interpreted as measuring temporal drift alone.

## Results recorded in this repository

The figures below are transcribed from the saved output files, rather than reconstructed from a new training run.

| Evaluation | Model | Accuracy | Attack recall | Attack F1 |
| --- | --- | ---: | ---: | ---: |
| Random-split baseline (stored results) | Random Forest | 99.92% | **99.90%** | 99.91% |
| Friday PortScan → Wednesday (stored results) | Random Forest | 71.25% | **20.16%** | 33.56% |
| Friday PortScan → Wednesday (stored results) | Logistic Regression | 72.70% | 24.42% | 39.18% |

Sources: [baseline metrics](results/metrics.csv), [baseline summary](results/run_summary.json), [cross-day metrics](results/cross_day_metrics.csv), and [cross-day summary](results/cross_day_summary.json).

**Correction to an earlier README value:** The saved Random Forest baseline recall is \`0.9989821143\`, which is **99.90%**, not 99.98%. The original cross-day result is \`0.2016293279\` (20.16%).

A previous README also reported that adding Thursday Web Attack training data improved cross-day Random Forest F1 from 33.56% to 50.32% and attack recall to 33.61%. The current \`src/train.py\` does implement combined Friday+Thursday training, but **the repository does not contain a saved output file or the complete historical setup needed to verify those particular improvement figures**. They should be treated as previously reported rather than independently reproduced results.

## Data and evaluation caveats

Dataset: [CIC-IDS2017 from the Canadian Institute for Cybersecurity](https://www.unb.ca/cic/datasets/ids-2017.html). The original CSV files are not included in the repository.

- **Binary labels:** The currently available code maps \`BENIGN\` to 0 and all other labels to 1 (\`ATTACK\`).
- **Different attack categories:** Friday afternoon's PortScan traffic and Wednesday's traffic contain different attacks. Cross-day performance here reflects changes in attack composition as well as collection conditions. It does not isolate time-based distribution shift.
- **The observed contrast is not a deployment claim:** These results do not establish detection performance in a live enterprise network.
- **Baseline provenance:** The random-split metrics and model files have been saved, but the original baseline training script and exact split construction are not currently in the repository. Their complete reproduction cannot be verified from the present code.
- **Feature selection:** The current script independently filters columns in each input file and then intersects the retained features. This can make the feature set depend on evaluation data; a stricter protocol would define the feature set using training data only.
- **No saved run from the current script:** \`src/train.py\` prints metrics but does not save model files or result CSVs. Do not assume the existing files in \`results/\` were generated by the current version of that script.

## Run the available combined-training experiment

The **current code** runs one experiment: train on sampled Friday PortScan **plus** Thursday morning Web Attack records, then evaluate on sampled Wednesday records. It fits Logistic Regression and Random Forest classifiers.

### 1. Install dependencies

Use Python 3 with a virtual environment:

\`\`\`bash
python -m venv .venv
# Activate the environment for your OS, then:
python -m pip install numpy pandas matplotlib scikit-learn
\`\`\`

The repository currently has **no pinned requirements file** or lockfile; exact package versions from the original runs are not recorded. The command above installs the libraries imported by the available training script, but has not been execution-tested here against the full source dataset.

### 2. Download and arrange data

Download the CIC-IDS2017 labeled flow CSV files from the [official dataset page](https://www.unb.ca/cic/datasets/ids-2017.html). Put these files in \`data/\`, preserving the exact filenames:

\`\`\`text
data/
  Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv
  Thursday-WorkingHours-Morning-WebAttacks.pcap_ISCX.csv
  Wednesday-workingHours.pcap_ISCX.csv
\`\`\`

Depending on the downloaded archive layout, you may need to extract and copy the CSV files into \`data/\`.

### 3. Execute the current script

From the repository root:

\`\`\`bash
python src/train.py
\`\`\`

The script:
1. Takes up to **30,000 rows** from each CSV with random seed **42**, where each file has at least that many rows.
2. Converts the \`Label\` column into \`BENIGN=0\` and \`ATTACK=1\`.
3. Converts features to numeric, removes all-empty, mostly-missing and constant columns, then aligns common columns across files.
4. Trains on Friday + Thursday samples (up to **60,000 rows**) and evaluates on Wednesday (up to **30,000 rows**).
5. Fits a \`StandardScaler\` and median imputer within the Logistic Regression pipeline; the Random Forest pipeline uses a median imputer.
6. Reports accuracy, balanced accuracy, attack precision, recall, F1 and false-positive rate to the terminal.

The Random Forest uses \`n_estimators=120\`, \`min_samples_leaf=2\`, \`class_weight="balanced_subsample"\`, and \`random_state=42\`. Logistic Regression uses \`max_iter=600\` and \`class_weight="balanced"\`.

**Reproduction status:** Code and data layout are documented, but the script has not been rerun here with original CIC-IDS2017 CSV files. It will not regenerate all the archived outputs automatically.
